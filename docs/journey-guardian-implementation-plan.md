## 1. 產品目標與交付邊界

使用者自己安排旅行，工具整理旅程的重要條件，在適當時間指出尚待確認的事項、原因與下一步。核心價值是減少遺漏、辨識資訊不確定性、保留備援行動。介面以手機為優先，第一版提供可安裝 PWA。

首版成功定義：使用者不登入、不提供 AI 金鑰，仍能建立旅程、完成六項檢查、離線查看既有內容、匯出與復原資料。AI 只是選配輸入及解說助手。未取得資料不能顯示安全通過；使用者勾選完成也不等於官方確認符合規定。

首版不包含：全自動旅遊規劃、機票住宿交易、完整路線搜尋、持續背景交通監控、保證推播送達、雲端帳號同步、多人即時協作、商品導購、原生 App、護照掃描與敏感證件保管。不要把這些功能當成必要依賴。

## 3. 架構決策

| 層 | 首版決策 | 實作理由及邊界 |
| --- | --- | --- |
| UI | 保留 React + TypeScript + Vite | 漸進改造，避免不必要的 Next.js／SSR 重寫 |
| 樣式 | 沿用可維護的既有方式，改為本地建置 | 移除執行期 CDN 腳本；字型與圖示不依賴離線外部下載 |
| 狀態 | React 狀態＋薄型 repository | 不先引入大型全域狀態框架；資料寫入途徑集中 |
| 持久化 | IndexedDB | 交易、schema version、備份復原；優先使用維護中的薄封裝，WP0 決定 idb 或既有合適方案並鎖版 |
| 判斷核心 | 純 TypeScript 函式＋版本化規則包 | 無 UI、網路、金鑰依賴，可重現與離線測試 |
| 驗證 | 沿用既有工具；結構驗證選單一方案 | 優先 Zod；已有相容驗證庫則評估沿用，避免重複 |
| 離線 | Service Worker＋PWA manifest | 快取應用殼、規則、必要靜態資產；不快取 AI 請求與金鑰 |
| AI | 單一供應商 adapter 起步，選配 BYOK | 不依賴 AI 完成核心操作；先做假資料測試再真人自備金鑰驗證 |
| 部署 | Cloudflare Workers Static Assets | 靜態資產部署起步，不預設 Worker 執行程式、資料庫或代理 |
| 驗證工具 | 現有單元測試＋Playwright＋型別／正式建置 | 依用途保留現有測試，必要時再統一 runner |

「後端在瀏覽器」的精確含義是：應用邏輯與資料庫在使用者瀏覽器執行，首版沒有我們維運的應用伺服器。選配雲端 AI 仍是外部服務。瀏覽器不會在關閉後持續執行守護任務。

初期以免費額度內零固定服務費為目標，不能保證永遠零成本。網域可先用平台免費網址；AI 費用由使用者的供應商帳戶負擔。部署前再核對當時官方免費限制。沒有使用者同意不得升級付費、綁計費服務或執行付費模型測試。

cloudflared 僅作開發展示或使用者自有 AI gateway 的選配入口。Tunnel 需要來源主機持續運轉，不取代靜態託管，也不自動提供應用身分驗證。臨時網址變動會改變瀏覽器資料來源範圍；不得拿隨機 Tunnel URL 當正式資料長期住所。自有 gateway 必須有驗證、來源限制、速率與請求大小限制，不得形成公開代理。

## 4. 六項檢查與資訊設計

主頁呈現下一個重要時點、需要處理的項目、資料待確認狀態。六項檢查可展開，不以大聊天框作首頁。每張卡至少有：影響、依據、資料時間、下一步、完成或暫緩操作。

| 編號 | 模組 | 必要輸入 | 輸出與不確定性處理 |
| --- | --- | --- | --- |
| G1 | 證件與入境 | 國籍／目的地／轉機需求、使用者確認事項 | 檢查項目及官方入口；不保存證件號碼，不自行斷言合法入境 |
| G2 | 行動通訊 | 裝置、相容性、網路需求、已購方案及啟用條件 | eSIM／SIM／漫遊／分享器／WiFi與離線選擇；未知相容性不等於不支援 |
| G3 | 行李 | 航空公司、艙等、物品及適用條件 | 可解釋風險與人工確認項目，保留現有可用清單功能 |
| G4 | 出發與機場交通 | 航班日期時區、航廈、出發地、已確認交通及緩衝 | 參考出發時間與備援待辦；缺必要輸入不產生看似精確的時間 |
| G5 | 回程與海關檢疫 | 返程目的地、物品分類、必要數量條件 | 官方查詢及申報待辦；不強迫記帳、不憑 AI 宣告可攜入 |
| G6 | 旅後回顧 | 自願回饋 | 有幫助／無幫助／時機不對／資訊錯誤／不清楚，回饋留本地 |

住宿先只保留可選的聯絡方式、入住期限及備忘，支援交通中斷時行動。保險與居家安全等延伸模組留待後續。

三條狀態軸必須分開：
1. 任務：未處理、處理中、完成、暫緩、略過。
2. 資料：已人工確認、待確認、缺資料、互相衝突、已到複核期限。
3. 適用性：適用、不適用、尚無法判定。

「完成」只代表使用者處理紀錄。重要輸入、規則或來源改變時，相關結果回到待複核，保留原先紀錄。不要用單一綠燈混合三種意義。

## 5. 資料與規則契約

所有資料使用穩定 ID、schemaVersion、createdAt、updatedAt。時間儲存可還原的時區資訊；旅程當地日期不得以使用者裝置時區直接推算。

| 實體 | 主要內容 |
| --- | --- |
| trips | 起訖日期、時區、目的地、航班與交通必要欄位、可選住宿聯絡 |
| tripInputs | 輸入值、來源類型、原文定位、confirmedAt；AI 草稿與確認值分離 |
| gateTasks | 模組、適用性、任務狀態、排程錨點、暫緩與略過理由 |
| gateRuns | 當次輸入快照／摘要、規則版本、輸出、計算時間、待複核原因 |
| rules | ruleId、版本、條件、所需輸入、固定訊息、來源與複核期限 |
| sources | 官方 URL、適用地區、人工複核紀錄、實際生效期間（若有） |
| items | 既有行李清單及其來源關係 |
| reminders | 本地提醒規劃、ICS UID、匯出版本；不偽稱外部提醒已送達 |
| events | 最少必要操作與自願回饋；不保存原始 AI 提示或金鑰 |

規則必須能回答：對誰適用、缺什麼資料、為何觸發、依據何在、何時複核、下一步是什麼。verified_by 必須代表真實人工審閱，AI 草稿只標 needs_check。review_due 是內部複核期限，不能假裝官方規定失效日。

函式介面建議為 evaluateGate(confirmedInputs, rulePack, clock) → findings。clock 可注入；相同輸入、規則、時間應產生一致結果。結果包含 ruleId、severity、evidenceState、missingFields、sourceRefs、actions；禁止從 UI 或 AI 偷渡判定。

規則包更新：下載 → 驗證格式及應用相容性 → 顯示差異 → 原子切換 → 選擇性重跑受影響項目。失敗保留最後可用版本，不用半套新舊規則。首版可隨靜態版本更新，無須先建遠端管理系統。

## 6. 本地資料可靠性與遷移

- 集中 repository 讀寫；元件不直接散寫 localStorage 或 IndexedDB。
- 既有 localStorage 遷移先提供備份，再以可重跑程序轉入；驗證成功前不刪除原資料，不以筆數上限靜默移除舊清單。
- IndexedDB 升級使用交易及版本測試。資料升級不可任意降版；舊程式遇到新 schema 應停寫並指引復原。
- JSON 備份含版本、資料數量與匯出時間，不含金鑰；匯入先驗證、預覽合併或取代影響，再交易式寫入。損壞檔不得留下半套資料。
- 加密備份可列延伸工作；首版若未做，明示匯出檔含私人行程，避免宣稱加密。
- 支援下載備份、刪除單趟／全部本地資料、儲存失敗訊息；嘗試請求持久儲存權限，但不能保證瀏覽器永不清除。
- 正式網域確定後保持穩定。不同網域、無痕模式、不同瀏覽器不共用資料；搬站必須匯出／匯入。
- 不設自動雲端同步、不自動將旅程送到分析平台。

## 7. AI 與金鑰安全

BYOK 解決開發者代付費用，並未消除使用者金鑰風險。首版先完成無 AI 版本；AI 增強版選一種已驗證可行的接入方式，不承諾所有供應商都能瀏覽器直連。

優先接入邊界：使用者自有、具驗證的 gateway；長效供應商金鑰留在其伺服器。進階瀏覽器直連只在供應商明確支援、風險揭露與使用者選擇下啟用；若供應商不支援，不用公開 CORS 代理繞過。尚未驗證的供應商不能出現在「可用」清單。

金鑰只放當前頁籤記憶體，清除連線或重新載入即失效；不得進 localStorage、IndexedDB、URL、錯誤回報、備份、事件或 Service Worker 快取。自訂 gateway 的目的端要明確確認，憑證不得隨端點切換帶往另一個主機。

AI 流程：
使用者選擇要送出的文字 → 預覽資料及供應商 → 主動送出 → 結構驗證 → 顯示草稿與來源定位 → 使用者確認關鍵欄位 → 決定性引擎重算。
日期、時區、航班、通訊啟用條件等不可自動覆蓋已確認內容。AI 不得改寫官方規則或把 needs_check 升級成已驗證。

設取消、逾時、輸入長度、輸出 token 上限及有限重試，避免無限重試費用。頁面預估不等於帳單硬上限；建議使用者於供應商端配置可用的額度管控。失敗回到手動流程。AI 說明以既有 findings 為輸入，不允許自行發明新規定。

防護：限制 CSP 來源、避免第三方執行腳本、AI Markdown 安全渲染、連結協定驗證、依賴鎖版、金鑰遮罩與網路請求目的端檢查。提示注入內容視為資料，不能賦予工具執行或自動修改旅程權限。

## 8. 排程、離線與匯出

D 為出發日、R 為返程日，依旅程時區計算。建議節點：G1 D-30／D-14；G2 D-21／D-3／抵達／回程；G3 D-7／D-1；G4 D-3／D-1；G5 R-1；G6 R+1。這是產品排程，不是官方期限。

晚加入旅程時，將過期但仍有用的任務合併成「現在處理」，不連發大量逾期通知。旅程改期、跨日航班、回程與出發時區不同、同日往返、取消旅程均有測試。只有同意啟用提醒才匯出日曆。

PWA 初次完整載入後，離線可開啟應用、讀寫旅程、執行本地規則及看已保存來源摘要。官方頁面與 AI 仍可能需要網路；清楚顯示資料快照時間。第一次完全離線尚未安裝時不能保證啟動。

ICS 是匯出當時的快照，不是訂閱同步；改期後提醒使用者更新外部日曆。穩定 UID 與 SEQUENCE 仍須驗證各日曆行為，不能保證匯入不重複或必然通知。PDF 優先採列印樣式與瀏覽器另存 PDF，清楚標示快照日期與未確認項目；需要自動產檔再評估額外依賴。

應用更新採提示刷新，不在填寫中直接切換版本。保存待編輯資料後更新，避免新版前端與舊資料契約錯配。回滾包含靜態資產與規則；資料 schema 需前向相容或備份復原，不能只回退網站便宣稱完成回滾。

## 10. 驗收矩陣

數量為最低起始案例，不以測試數量取代規則完整性。固定資料需標測試情境，不能當成最新官方事實。

| 類別 | 最低驗證內容 |
| --- | --- |
| 原功能回歸 | 既有行李建立、編輯、勾選、刪除、保存／還原流程逐項對照 |
| 行李 | 至少30案例，含至少5種資訊不完整／模糊物品 |
| 通訊 | 至少8案例，含相容未知、不支援、已購、不同啟用計時、無AI |
| 海關檢疫 | 至少20案例，覆蓋目的地／分類／缺輸入／過複核期；結論有來源 |
| 交通 | 至少5案例，含跨日、缺時區、資訊過期、替代未確認、緩衝不足 |
| 證件及回顧 | 缺國籍／目的地、轉機、已確認後改期；回饋可修改／刪除 |
| 排程 | D/R跨日、裝置不同時區、晚加入、取消、改期、暫緩到期 |
| 資料 | 舊格式遷移、重複匯入、毀損檔、容量不足、交易中斷、舊程式遇新schema |
| AI | 無key、401／429／逾時、取消、結構正確但語意錯誤、提示注入、敏感內容最小化 |
| 資安 | 金鑰不出現在儲存／快取／日誌／匯出；端點切換不帶錯憑證；HTML與URL注入 |
| 離線 | 載入後斷網重開、建立／修改、來源過期、更新中斷、恢復網路 |
| E2E | 新旅程→六模組→關閉重開→改期→備份→清除→復原；不需登入或金鑰 |
| 手機與無障礙 | 窄螢幕、鍵盤、表單標籤、焦點、對比、觸控、載入／空白／錯誤狀態 |

先完成瀏覽器驗證，再集中以 Samsung Galaxy A57／Android 16 試用，避免每次微調就要求手機更新。未實際取得裝置的測試標為待驗收。真實旅程由使用者提供，不推測十一月底行程細節。需人工查核官方規則者留為待複核，不偽造驗證紀錄。

技術完成門檻：型別檢查與正式 build 通過、相關單元與整合／E2E 通過、核心離線／復原通過、已知阻斷缺陷清零、來源狀態正確、無已知金鑰洩漏路徑。測試腳本成功但沒走到主要流程不算通過。

發布阻斷：資料遺失／無法復原、把未知判通過、AI自行覆寫確認值、未授權外傳、無法開啟核心頁面、重要錯誤無提示。人工旅程驗收與真實供應商驗證未完成時可交工程預覽，但不可宣稱全部完成正式上線。

## 11. 執行紀律與成本控制

1. 使用功能分支或現有安全開發分支；不覆蓋使用者變更、不 force push、不自動刪除舊資源。
2. 先完成可離線無金鑰操作，再增加 AI；以垂直切片交付，避免只做漂亮空頁。
3. 未提供 AI 金鑰不阻擋核心開發。真實金鑰由使用者在安全介面輸入，禁止要求貼在對話或提交到 Git。
4. 不新增付費方案、不設定付款、不部署公開站點，除非已有相應明確授權。可以準備部署設定與本地可審查預覽。
5. 測試環境故障要附命令與簡短錯誤，標成 blocked；不得把未執行寫成通過。
6. 完成每包留下差異、測試證據、未解決問題。工作延續時讀 progress，不重頭重構。
7. 精準工期待 WP0 盤點後估算。以工作包交付與驗收為承諾，不先用樂觀天數掩蓋未知。
