# 出國實測方案

目的：縮短旅客從收到航班變動通知到採取第一個正確行動的時間。

1. 手機入口使用 Android USB 連線預載正式 PWA，沿用固定 localhost 網址，資料留在該手機。拔線後以飛航模式重開，修改物品並再次重開驗證。
2. 每筆航班事件獨立產生待辦。取消或缺可靠新時間時先查航空公司；已知上網到期不晚於起飛時先處理通訊，再核對已關聯的接送，住宿僅列為待查。保留原時間、聯絡資料與查證原因。處理狀態隨事件保存在旅程備份，相關依據變更後重新提示。
3. 首頁讀取現有航班、住宿、通訊與行李重量，集中顯示缺項或超重；直接連到資料來源。保留使用者先前填寫的檢查卡與備註。
4. 驗收取消、缺時區、跨時區到期、另一航班的交通排除、處理後重開及資料異動。用同一個模擬改期情境，比較平常方法與工具的耗時、漏查項數、錯把未知當確定的次數。測試旅程與正式旅程分開建立。

## Android 上機

Android 手機需有 Chrome、開啟 USB 偵錯，並接受這台 Mac 的連線。接線後從 guardian-work 執行 `bash scripts/android-field-preview.sh`。它會建置、啟動僅監聽本機的預覽，並在手機 Chrome 開啟固定網址。首次看到「基本頁面已儲存於此瀏覽器」後，建立演練旅程，等「已儲存至本機」，拔線並開飛航模式。關閉頁面、以原網址重開、修改一筆待辦再重開。通過後才建立正式行程，並從工具下載備份。若手機有多台 ADB 裝置，可用 ANDROID_SERIAL 指定。Mac 上按 Ctrl+C 結束預覽。
